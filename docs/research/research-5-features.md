# Research 5 — Competitor features, design risks, recommendations (COMPLETE, 2026-08-19)

## Headline: direct prior art
**Epson Document Capture Pro (DCP) v3.3** is the closest existing product to the FG Scanner spec: per-job wizard Scan/Save/**Index**/Send/Confirm (max 30 jobs); user-defined typed index items (Barcode ≤10, OCR-zone ≤10, MRZ ≤20); index file **CSV or XML (Windows only)** with **append mode** ("Add") and **Index Separation = Document** (one row per document); separation via patch codes 1/2/3/4/6/T, 1D+2D barcodes (≤4/page, ≤250 chars), blank pages, two-stage. Weaknesses = our gap: opaque/undocumented format options, no DB behind the file, model/license-gated features, Mac version has no Index step. Canon CaptureOnTouch's CSV writer is defective. ScanSnap Home extracts rich receipt/invoice data but export is manual post-hoc CSV; ScanSmart naming = prefix+date+counter only. Kofax Capture/Express = professional analogue: 11 typed field types, validation masks, pick lists w/ force-match, Required/Verify/Hidden/**Sticky**/Total attributes, DB-lookup auto-fill, system tokens {Batch Name}{Operator}{GUID}{Sequence}, zonal OCR, per-field zoom memory, red invalid highlight. Paperless-ngx = richest OSS reference: 9 custom field types, auto ML matching, workflows (trigger→action incl. webhook), consumption dirs, barcode engine (PATCHT separator, ASN, tag-regex mapping), Jinja filename templates + slugify, checksum dedupe, dual storage (original never overwritten + PDF/A archive), trash 30-day, audit log, FTS query language. Rossum: calibrated per-field confidence 0.975 auto-accept threshold, error-vs-warning rule severities, duplicate icon, automation-rate stats.

## B. Design risks / edge cases (all addressed in PLAN §5.2)
1. CSV-as-store is the core risk → SQLite truth, CSV regenerated atomically on commit.
2. Excel lock → temp+rename, retry, notice. 3. Excel mangles data → ISO dates, optional xlsx. 4. UTF-8 BOM, CRLF, RFC 4180, configurable delimiter; descriptions contain commas/newlines. 5. Document vs page vs group undefined → 3-level model. 6. AI failure semantics → status enum + retry queue, not Yes/No. 7. Cost/rate control → estimate + backoff; Flash thinking billed. 8. Duplicate names → immutable GUID key, filename is attribute. 9. External renames → checksums + reconcile. 10. Re-OCR semantics → replace .md, old to trash. 11. Missed-page ordering → sequence in DB, not filenames. 12. Delete page → soft delete + CSV update. 13. Date locale ambiguity → ISO. 14. Windows filename rules (reserved chars/names, MAX_PATH, trailing dot/space) → slugify. 15. Profile evolution vs old CSVs → schema versions + manifest + migration rule. 16. Foreign index.csv in picked dir → detect/warn. 17. Concurrency → SQLite WAL; document local-disk-only or lock protocol for shares. 18. CSV injection (=,+,-,@ prefix — attacker-printable!) → escape. 19. OneDrive/Defender interference → File.Replace + tests. 20. Config-vs-state conflation in OCRed/AI columns → profile toggle vs row status.

## C. Recommendations
C1 Barcode/patch: Patch-T first (printable sheets menu); ZXing.Net software detection (300 DPI, upscale option, first-N-pages, keep/drop separator); value-bearing barcodes (ASN + barcode→field regex mapping); hierarchy: fixed count → blank → patch-T → prefix barcode → two-stage → (later) classifier.
C2 Blank pages: NAPS2 white/coverage thresholds; per-profile policy drop|flag|separator; always journal dropped pages; don't let removal fight separation (DCP trap).
C3 Naming: NAPS2 tokens + $(group) $(doc) $(page) $(field:X) $(barcode); slugify everything; collision suffix; filenames are presentation — sequence lives in DB; sidecars share base name.
C4 Model: Group(batch)→Document(CSV row, GUID, ordered pages)→Page(file, checksum, seq, statuses). One row per document (= per image in v1). Concatenate per-page .md into per-document .md when multi-page arrives; per-document AI description (first page) cuts cost.

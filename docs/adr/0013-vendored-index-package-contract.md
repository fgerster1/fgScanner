# 13. The index-package contract is vendored from JimsStuff, never owned here

Date: 2026-09-30

## Status

Accepted

## Context

The case-index batch loop (JimsStuff `SPEC-2026-005-contract-slice` — a
different spec from this repo's own SPEC-2026-005, the memo spec) moves
packages between the JimsStuff portal and FG Scanner. Two programs in two
repos deploy independently, so the format they share needs one authoritative
home, and each side's tests need to parse the same bytes the other side
committed. A monorepo merge and a separate contract repo were both rejected
in the parent spec (JimsStuff SPEC-2026-003 §08): the apps never deploy
together, and a third repo is broker cosplay for one developer.

## Decision

The contract — JSON Schemas, prose README, golden sample package, golden
`results.json` — lives in **JimsStuff `docs/contract/`**. This repo carries a
**vendored copy** under `docs/contract-vendored/`, produced only by
`build/sync-contract.ps1` (one-way, JimsStuff → here, stage-then-swap), and
never edited by hand. The sync writes the same `sync-manifest.json` to both
repos. `ContractSyncTests` proves the vendored bytes against the vendored
manifest; a cross-repo test compares the two manifests whenever the repos sit
side by side, because a vendor gone stale *together with* its manifest is
self-consistent and invisible to any per-repo check. `.gitattributes` pins
the vendored tree `-text` (the hashes are over exact bytes) and `.gitignore`
carries `!docs/contract-vendored/**` so no depth-insensitive ignore rule can
silently drop a contract file from a commit.

Golden files are generated by the real programs — JimsStuff's
`tests/regolden_contract.py` for the package, this repo's `RegoldenResults`
test (env-gated, target-validated) for the results — and committing the
regenerated bytes is the deliberate act of changing the contract.

## Consequences

Any contract change is a two-repo commit, enforced by tests rather than
discipline. FG Scanner code never reasons about the portal's files directly;
`FgScanner.Core.IndexPackages` parses only the vendored shapes and refuses
everything else (the total-refusal contract in `PackageReader`). The
index-package contract shares no files, folders or writer code with the
capture evidence contract (`evidenceExport`), and this ADR is the pointer the
CLAUDE.md rule stands on.

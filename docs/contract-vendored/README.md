# The index-package contract

This folder is the law for every byte that moves between the JimsStuff portal and
FG Scanner in the case-index batch loop (SPEC-2026-003 §08, made real by
SPEC-2026-005). Both programs' test suites parse the files here; FG Scanner carries
a **vendored copy** synced one-way by `build/sync-contract.ps1` in its own repo.
Each suite's SHA-256 manifest test reds an edit made without re-syncing; a vendor
gone stale *together with* its manifest is self-consistent and invisible to a
per-repo check, which is why both suites also compare the two repos' sync
manifests wherever the repos sit side by side — a sync is always committed in
BOTH repos.

> **formatVersion 1 is provisional** until phase 4 ships FG Scanner's package mode
> to Jim. Until then, changing the format is an ordinary edit of the schemas and the
> golden files in one commit — nothing has left the dev machine, so the release
> rules below do not yet bind.

## What an index package is

A folder the portal exports for one batch of documents Jim will index in FG Scanner:

```
PKG-0001/
  manifest.json     what this is, which versions, and the checksum of every file
  seed.json         per document: its pages, current decisions, open AI suggestions
  people.json       the people pull-down (register survivors only, never merged losers)
  subjects.json     the subject vocabulary (soft-deleted rows included, marked inactive)
  doctypes.json     the document-type vocabulary
  images/           one copied image per page — copies, never moves (Evid.R. 1003:
                    the originals never leave the portal's folders)
```

FG Scanner opens the folder, Jim answers, and FG Scanner writes **`results.json`**
(a small file Jim uploads on the portal's Case Index page, SPEC-2026-007). The portal
serves the folder as ONE stored zip with these entries at its root; FG Scanner
extracts it and opens the folder as above (its ADR-0015). The zip is transport only:
every rule here applies to the extracted folder, unchanged.

`manifest.json` is deliberately **not** part of the capture evidence contract: its
marker key is `indexPackage: 1`, never `evidenceExport`, and no file or folder is
shared with the capture flow. The two contracts must never touch (the rule lives
in FG Scanner's CLAUDE.md, "The index-package contract is vendored, never
edited").

## Byte rules (what makes the golden tests possible)

Every JSON file in a package and in `results.json` is written exactly like this:

- `json.dumps(obj, indent=2, sort_keys=True, ensure_ascii=False)` plus one trailing
  `"\n"`, encoded UTF-8, **LF line endings**, no BOM.
- No generated-at timestamp inside any hashed content. Issue time lives in the
  portal's `packages` table; decision times live inside `results.json` answers
  where they are data, not noise.
- `manifest.json`'s `sha256` map covers **every other file in the package** by
  relative path (forward slashes). The **package checksum** — the value registered
  in the portal's `packages` table and echoed by `results.json` as
  `packageChecksum` — is the SHA-256 of `manifest.json`'s own bytes. One file
  changed anywhere therefore changes the package checksum.
- Golden files under `golden/` are **generated, never hand-edited**:
  `python tests/regolden_contract.py` (JimsStuff) rebuilds the package with the
  real exporter, and the FG Scanner test `RegoldenResults` — run with the
  `FG_REGOLDEN_RESULTS` environment variable pointing at this folder's `golden/`
  directory — rebuilds `golden/results.json` with the real writer. Committing
  the regenerated bytes is the deliberate act of changing the contract.

## Versioning

Two numbers, two different jobs (parent spec §08):

- **`formatVersion`** — the structure. FG Scanner **refuses** a package whose
  formatVersion it does not know, with exactly this message:

  > This package needs a newer FG Scanner — close and reopen the app to update.

  The portal importer accepts results with formatVersion **N and N-1**. Additive
  change (new optional keys) is the standing default; the schemas allow unknown
  extra keys everywhere for exactly this reason, while every **required** key is
  load-bearing and may never be renamed.
- **`vocabularyVersion`** — a diagnostic stamp, never a gate. Person ids are
  permanent and merges chain, subjects and doc types soft-delete only — so a
  results file built against ANY older vocabulary stays importable forever. A test
  imports the golden package against a register where a fixture person was merged
  and a subject withdrawn, to keep that sentence true.

## Release discipline: the reader updates first

Copied from SPEC-2026-003 §08 so it lives beside the schemas it protects. Binding
from the first FG Scanner release that ships package mode (phase 4):

1. **Portal → scanner format change**: publish the FG Scanner release that *reads*
   version N first; confirm Jim's station updated (the echoed `appVersion` in his
   last upload); only then flip the exporter to emit N.
2. **Scanner → portal change**: deploy the portal importer first, publish the
   FG Scanner release second.
3. **Never** drop N-1 import support while the `packages` table shows an
   outstanding (issued or partial) package.

## The files here

- `schemas/*.schema.json` — JSON Schema (draft 2020-12), one per contract file.
- `golden/package/PKG-0001/` — one committed sample package, built from the test
  fixture register by the real exporter (AC-2 proves it byte-for-byte).
- `golden/results.json` — the committed sample answer file, written by the real
  FG Scanner `PackageWriter` over that package (AC-3), imported by pytest (AC-4).
